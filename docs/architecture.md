# Архитектура UnifiedMessenger

## Границы текущего этапа

Решение содержит один WPF-проект и один проект модульных тестов. Этап 2 создаёт ровно один экземпляр Telegram WebView2. Другие мессенджеры, несколько аккаунтов, системный трей, уведомления и OAuth не подключены.

## Слои

- `Models` — сериализуемые настройки, экземпляры и определения сервисов.
- `ViewModels` — состояние окна и коллекции, не зависящие от визуальных контролов.
- `Views` — WPF-разметка; code-behind ограничен инициализацией и сохранением геометрии окна.
- `Services` — каталог сервисов и чистые операции над аккаунтами.
- `Services/Persistence` — пути данных и атомарное JSON-хранилище.
- `Services/Security` — безопасные имена профилей и политика верхнеуровневой навигации.
- `Services/Notifications` — безопасное распознавание числа только из заголовка страницы.
- `Services/WebView` — runtime-проверка, создание WPF-контрола, профиль, навигация, внешний браузер и восстановление после сбоя.
- `Services/Gmail` — явная граница будущего Gmail API-модуля.

## Запуск и зависимости

`App` создаёт `ServiceProvider`, регистрирует зависимости и загружает настройки до показа окна. Provisioner создаёт Telegram и атомарно сохраняет его GUID до запуска WebView2, чтобы профиль авторизации оставался связан с тем же аккаунтом даже после аварийного завершения. `MainWindow` создаётся контейнером и связывает визуальный контейнер с менеджером сессии.

## Конфигурация

`AppSettings` имеет номер схемы. `JsonSettingsService` записывает форматированный JSON во временный файл в том же каталоге, повторно десериализует его для проверки и заменяет основной файл. При синтаксически повреждённом документе исходный файл перемещается в резервную копию, а приложение получает настройки по умолчанию и предупреждение для пользователя.

## Каталог сервисов

`BuiltInServiceCatalog` — единственное место со стартовыми адресами и списками разрешённых доменов. Gmail помечен как не-WebView сервис и не имеет стартового URI. Каждый будущий аккаунт представлен отдельным `ServiceInstance`; имя профиля образуется только из GUID.

## Последующие этапы

`IWebViewSessionManager` владеет жизненным циклом текущего контрола, задаёт `CreationProperties` до инициализации, подписывается на события навигации и освобождает COM-ресурсы при закрытии. Несколько профилей, удаление аккаунтов и переключение относятся к этапу 3. Трей, уведомления, режимы памяти, разрешения и Gmail остаются разделёнными по следующим этапам.
