# Архитектура UnifiedMessenger

## Границы текущего этапа

Решение содержит один WPF-проект и один проект модульных тестов. Этап 3 поддерживает независимые аккаунты Telegram, WhatsApp, MAX и VK Мессенджера. Системный трей, уведомления, режимы экономии памяти и OAuth не подключены.

## Слои

- `Models` — сериализуемые настройки, экземпляры и определения сервисов.
- `ViewModels` — состояние окна и коллекции, не зависящие от визуальных контролов.
- `Views` — WPF-разметка; code-behind ограничен инициализацией и сохранением геометрии окна.
- `Services` — каталог сервисов и чистые операции над аккаунтами.
- `Services/Persistence` — пути данных и атомарное JSON-хранилище.
- `Services/Security` — безопасные имена профилей и политика верхнеуровневой навигации.
- `Services/Notifications` — безопасное распознавание числа только из заголовка страницы.
- `Services/WebView` — runtime-проверка, создание WPF-контрола, профиль, навигация, внешний браузер и восстановление после сбоя.
- `Services/Gmail` — явная граница будущего Gmail API-модуля.

## Запуск и зависимости

`App` создаёт `ServiceProvider`, регистрирует зависимости и загружает настройки до показа окна. Настройки Этапа 2 мигрируются до схемы 2 без изменения GUID и `ProfileName` существующего Telegram. `MainWindow` создаётся контейнером и связывает визуальный контейнер с менеджером сессий.

## Конфигурация

`AppSettings` имеет номер схемы. Схема 2 добавляет `PendingProfileDeletions`; отсутствующее поле получает пустое безопасное значение. `JsonSettingsService` записывает форматированный JSON во временный файл в том же каталоге, повторно десериализует его для проверки и заменяет основной файл. При синтаксически повреждённом документе исходный файл перемещается в резервную копию, а приложение получает настройки по умолчанию и предупреждение для пользователя.

## Каталог сервисов

`BuiltInServiceCatalog` — единственное место со стартовыми адресами и отдельными списками разрешённых доменов. Gmail помечен как не-WebView сервис и не предлагается в диалоге Этапа 3. Каждый аккаунт представлен отдельным `ServiceInstance`; имя профиля образуется только из GUID.

## Последующие этапы

`IWebViewSessionManager` лениво создаёт контрол при первом выборе аккаунта, задаёт `CreationProperties` до инициализации и хранит отдельную сессию по `ServiceInstance.Id`. Отключение освобождает контрол без удаления профиля. При подтверждённом удалении очищается только соответствующий профиль; занятый каталог записывается в очередь повторной очистки следующего запуска. Трей, уведомления, режимы памяти, разрешения и Gmail остаются разделёнными по следующим этапам.
